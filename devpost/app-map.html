The whole app in one path

browser (app/workspace/[packId]/page.tsx)
  └─ Workspace.tsx  — editor, run button, streaming reader
       │  POST /api/run  { packId, prompt }
       ▼
app/api/run/route.ts
  ├─ lib/limits.ts            rate limit, daily budget, body cap, timeouts
  ├─ lib/fixtures/load.ts     picks the private set, else labelled samples
  │    └─ lib/fixtures/schema.ts  Zod validation of every case
  ├─ lib/run.ts               runs the six cases, 3 at a time, streams events
  │    ├─ lib/model/client.ts     OpenAI-compatible call + failure classification
  │    ├─ lib/validators/deterministic.ts   Tier A — rules, no model
  │    ├─ lib/validators/judge.ts           Tier B — constrained judge
  │    ├─ lib/redact.ts           withholds a response that echoes its input
  │    └─ lib/scoring.ts          aggregates states into a score
  └─ streamed NDJSON: meta → case → case → … → done
       ▼
Workspace.tsx
  ├─ lib/regression.ts   compares this attempt with the previous one
  ├─ lib/prompt-diff.ts  line-level diff of the two prompts
  ├─ lib/lesson.ts       "what this attempt shows", from criteria actually tested
  └─ lib/export/markdown.ts  downloadable report built only from local state

Library modules that carry the product's promises

ModuleResponsibilityPromise it keeps
lib/fixtures/load.tsReads PACK_FIXTURES_JSON_B64 (or raw JSON), validates with Zod, falls back to fixtures/sample/.Hidden inputs stay server-side; a fallback is always labelled, never silent.
lib/run.tsOne call per case with the learner's prompt verbatim, three in flight, one event per resolution.Six real evaluations, streamed as they land — no progress simulation.
lib/validators/deterministic.tsJSON shape, exact keys, absent values, amount sets, request counts, word limits, phrase rules, fact retention.Most verdicts are rules, so they can be read and re-derived.
lib/validators/judge.tsOne Tier B criterion per pack, judged by a second model that never sees the learner's prompt.The judge cannot be talked into a pass by prompt wording.
lib/redact.tsWithholds a response that reproduces the hidden input; span mode by default, whole-input-only for rewrites.Hidden text can't leak through a model's echo, but correct answers stay visible.
lib/scoring.tsPass / fail / uncertain / unresolved → score and denominator.Uncertain leaves the denominator; unresolved is never counted as a failure.
lib/regression.tsObserved flips, comparability checks, optional hypothesis gated on a single flip and a small diff.Observation and explanation are different types, and the app says which one it is giving.
lib/limits.tsPer-IP rate limits, daily model-call budget, body cap, timeouts; Upstash when configured, otherwise process memory.A public endpoint that spends money is bounded, and the README says where the bound is weaker.
lib/model/client.tsOpenAI-compatible call, one bounded retry for a rate-limit, classification of rate limit / outage / timeout.A provider problem is reported as a provider problem.

Where the secrets are (and aren't)

  • GROQ_API_KEY — server-only Vercel environment variable; read in lib/model/client.ts and never exported to a component.
  • PACK_FIXTURES_JSON_B64 — server-only; the hidden inputs and acceptable answers.
  • The browser receives case results, never case inputs. The export is assembled from browser state, so it cannot include one.
  • .env*, .fixtures/ and devpost/learner-profile.md are ignored; git log -p was scanned for key material and none was ever committed.

Tests and scripts

  • tests/*.test.ts — 15 files, 145 Vitest tests, no network. They cover validators, scoring, regression, redaction, fixtures, limits, export, lesson and provider failure handling.
  • tests/flow.spec.ts — one Playwright pass against tests/support/fake-provider.mjs, proving progressive rendering, the export contents and the regression panel deterministically. Its scores are stub data and are never cited as model results.
  • scripts/live-check.mjs — drives the deployed build against the real provider and writes the screenshots in devpost/screenshots/.
  • scripts/probe-provider.ts — measures which models the key can reach, latency, JSON-mode support and rate-limit headers.
